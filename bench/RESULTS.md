# tar-bend benchmark — btar vs GNU tar

Generated by `tools/bench_release.sh` (median wall time; peak RSS = max over runs, from
Python `wait4` accounting of the process tree's largest member).

- date: 2026-10-25 22:25:09 UTC
- host: agheieff (24 cores: AMD Ryzen 9 7900X 12-Core Processor, 61.9 GiB RAM, kernel Linux 7.2.11-arch1-1)
- filesystem for temp trees/archives: tmpfs (`/tmp`), warm page cache
- btar: `btar 1.2.0` (1898112 bytes), native, default threads (= 24)
- GNU tar: `tar (GNU tar) 1.35`; gzip: `gzip 1.15` (`tar -z` = level 6); Bend: `bend 2.0.39`
- gzip in btar is pure Bend: streaming decoder (single-threaded), segment-parallel encoder
  (all cores). No size caps. The v1.0.0 numbers are kept in docs/release-verification.md.

## notes

- Every operation uses the tool's own archive (create writes it, list/extract read it back);
  extraction destinations are fresh per run and removed outside the measurement.
- This is a report, not a gate: slower-than-GNU numbers are recorded, not failures.
